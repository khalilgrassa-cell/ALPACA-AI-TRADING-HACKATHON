The brief01

Three rules, non-negotiable.

The hackathon's requirements shaped the architecture from day one — none of them were optional, so the pipeline was built to satisfy all three at the protocol level, not just in spirit.

Autonomy

The agent has to act on Alpaca's Trading API on its own — no human clicking "submit" per trade.

MCP, not REST

Every Alpaca call — quotes, chains, orders, positions — goes through Alpaca's official MCP server, the same tool-calling surface an LLM uses.

Options, not equity

The strategy has to trade options contracts, with real strike/expiry/greeks decisions — not just buy-and-hold shares.

Architecture02

Six stages, one chain per cycle.

Only two stages actually need a model's judgment. The other four are exact math or a fixed tool-call sequence — so that's what they are, in plain code.

Deterministic — 4 stages

Is the market open. Rank 168 symbols by momentum, keep the top 3. Pick a contract by delta, size the position. Submit the order, manage the exit. Zero judgment calls — so zero model latency, zero model failure mode.

LLM-driven — 2 stages

Sentiment reads the news. Strategy picks the trade shape. Both run on Groq, with model fallback and a second account for overflow — see next slide.

AI logic03

Judgment, clamped in code.

Both LLM agents are free to reason, but neither can act outside a boundary that's enforced by Python — not just asked for in the prompt.

  • SentimentReads recent news for a candidate. Can only push the momentum signal toward NO_TRADE — it can veto, but it can never invent a trade or flip direction. Enforced by _clamp_signal.
  • StrategyGiven the signal + sentiment + momentum strength, picks a long call, a long put, a risk-reversal combo, or no trade. Can never point a different direction than the signal it was handed. Enforced by _clamp_strategy.
  • InfraGroq-hosted, with automatic fallback across several models per call, then a second, genuinely separate Groq account once the first is exhausted for a turn — the daily token ceiling that once stalled a live cycle.
Risk gates04

Six checks between a signal and a fill.

Position size

1% of equity per trade, capped at 5 contracts.

Cycle cap

5% of equity max new risk across every candidate in one cycle.

Liquidity

Reject any contract with no bid, or spread over 25% of mid.

Delta targeting

Strike picked by proximity to 0.30 delta, not a flat % — adapts to each name's own volatility.

Stop-loss hold

30-minute minimum hold before a stop-loss can fire, so spread noise can't trigger it.

Combo sequencing

A 2-leg combo's short leg only fires after the long leg is confirmed filled.

Debugged live05

The bugs that only a live account finds.

Each of these only surfaced against real Alpaca and Groq responses — not something a mock would have caught.

Take-profit / stop-loss asymmetry
+10% take-profit against a -20% stop-loss meant every losing streak outweighed every win. Fixed to a symmetric ±20%.
Option chain exhausted by one side
get_option_chain's result limit is shared across the whole strike range — calls alone could fill it before a single put, or a genuinely OTM strike, was ever reached. Fixed by fetching each option type in its own one-sided range.
Groq's token cap is org-wide, not per key
A second API key on the same Groq account shares one budget. Real relief needed a genuinely separate account — confirmed live against an actual 429 on Groq's daily token cap.
Infra & testing06

No server, no shortcuts.

30 / 10 min

Full pipeline every 30 minutes, exit checks every 10 — both GitHub Actions jobs, fired by an external scheduler, capped at a 10-minute timeout so a hang can't eat a slot silently.

131 tests

Fully mocked — strategy math, the LLM tool-calling loop, every agent's direction/veto clamp, and the full orchestrator wiring — no live credentials needed to verify correctness.

  • SecretsAlpaca and Groq credentials live only in GitHub Actions secrets — .env is gitignored and checked before every push.
  • DeployDocker + docker-compose for local runs; GitHub Actions for the scheduled live pipeline — no server to provision or babysit.
